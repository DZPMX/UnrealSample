Elena 实时辅助骨骼求值
======================

本轮交付为 C++ 代码、原始驱动数据和待执行的接入脚本。用户选择保留当前 UE 会话，因此尚未链接/加载新模块，也没有执行资产接入。当前 ABP 仍为原来的版本。

实现范围
--------

`FAnimNode_ElenaRig` 从当前输入姿态读取 404 个直接驱动节点，按 elena-base.pak 的 8 个分组、12 个命令块运行 17 类原始命令，再覆盖 144 个派生节点。144 中包含 25 个颈部节点、19 个睫毛节点以及 100 个身体辅助节点；组节点也计入这些数量。

身体辅助节点包括肩膀、锁骨周围、胸部、手臂扭转、肘、腕、大腿、膝、踝等。完整骨骼名单见 `Plugins/U4PackageDemo/Source/UnrealSample/ElenaRig/Data/RigBinding.json`。

生成数据使用 `Plugins/U4PackageDemo/Source/UnrealSample/ElenaRig/Data/RigProgram.bin`，包含原始命令、参数、求值顺序和参考 SQT。运行时不读取游戏 EXE 或 PAK。原程序仅用于本轮独立对照。

移植范围为姿态计算及其读写顺序。游戏自身的计时、性能计数、函数栈保护和调用约定寄存器管理没有作为运行时功能移植；离线参考中的帧上下文查询走其空上下文计数分支，姿态命令和参数保持原样。数值证据比较的是姿态及工作区，不包含这些游戏性能统计状态。

节点每次从原始参考输入和当前直接驱动姿态重新求值。已烘焙的辅助轨道不作为求解器驱动输入，开启时由本次结果覆盖。`bEnabled=false` 时输出原输入姿态，包括原动画已有的辅助轨道。节点不修改曲线、属性或现有褶皱 EventGraph。工作内存和输出保存在每个节点实例内，无共享可变求解缓冲。

UE 适配处理米到厘米、根骨骼的全局 Y/Z 转换、非根骨骼的局部 Y 反射，并用实际 UE 父骨骼换算派生节点的局部姿态。当前缺失于 Compact Pose 的直接节点使用源参考输入，缺失派生节点不写入；其他 LOD 的最终效果未验证。本实现面向此项目的 Win64 Elena SK，没有实现头发/衣服的物理模拟。

已执行的验证
------------

* 原程序与移植 VM：644 个单命令样本，覆盖全部 17 类命令，比较全部四个工作内存区，位模式无差异。
* 完整求值链：88 个姿态，包含参考姿态、060–100 各 9 帧、32 个关节扰动姿态、9 个混合姿态以及 1 个从当前 UE 读回的输入姿态。比较 548 个节点的世界矩阵和局部 SQT，位模式无差异，无非有限数值。
* AddressSanitizer：644 个单命令样本通过，无报告的越界或释放后访问。
* UE 5.7.4 UHT 和项目 C++ 的 `-NoLink` 编译通过。没有链接、热重载或替换当前编辑器 DLL。
* 独立 VM 测试平均约 0.078 ms/姿态；不包含 UE 节点输入转换、输出回写、动画线程调度和渲染，不代表完整游戏帧耗时。
* ABP 文件与本轮备份哈希相同；UE 编辑器进程保持原 PID 3216。

证据位于 `Saved/Codex/Elena_RuntimeRig_20260923`：`CommandResults.txt`、`ChainResults.txt`、`UE_NoLink_Build.log`、`UE_NoLink_Build_Final.log`、`UEInputVerification.json`、`FinalReviewChecks.json`。

尚未验证及已知差异
------------------

上述逐位一致只适用于相同源空间输入及已执行的样本，不证明所有浮点输入和平台均相同。尚未运行 UE 新节点、编译接入后的 ABP、验证最终骨骼回写、PIE、Sequencer、手动改姿态、多实例并发及运行时开关。

当前动画导入数据已有精度/姿态差异。070 第 0 帧从 UE 反算输入后，相比同帧原始输入，全套求值的辅助节点位置最大差约 0.047 cm；相比之前仅恢复部分求值链的 UE 颈部烘焙，颈部位置最大差约 0.423 cm。两者比较对象不同。这一差异尚未完成画面对照或逐节点归因，不应据此宣称角色外观已完全复原。UE 的 FTransform 分解和非均匀缩放组合也需在实际节点回写后验证。

之后的接入顺序
--------------

1. 正常保存并关闭 UE 后，完整构建 UnrealSampleEditor（本轮只做了 NoLink，新增编辑器模块尚无 DLL）。
2. 重新打开项目，在 UE Python 中执行 `Plugins/U4PackageDemo/Scripts/ElenaRuntimeRig/install_runtime_rig.py`。脚本创建 `DA_Elena_SourceRig`，在现有 `ABP_Elena_Wrinkles` 的 AnimGraph 中接入 `LinkedInputPose → Elena Source Rig → Root`，新增并连接 `EnableRealtimeRig` 布尔变量，然后编译 ABP。脚本已通过语法检查；新增节点相关步骤还未执行验证。
3. 检查脚本返回的连接和编译结果，完成姿态/画面对照后保存这两个资产。脚本默认留下未保存状态，便于检查；不保存其他资产。
4. 接入后，通过后处理 AnimInstance 的 `EnableRealtimeRig` 控制此辅助骨骼求解器。关闭后沿用原输入动画，现有褶皱材质更新继续执行。

最终复核
--------

复核独立于实现进行，覆盖所有新增源文件、数据清单、接入脚本和项目配置差异。检查了求值顺序、跨组依赖、输入/输出覆盖、节点复制和初始化、Compact Pose 映射、曲线保留以及关闭回退路径。

复核中发现生成器把部分标量内存读取扩成了 16 字节，已改为原始 4 字节读取；随后重新执行数值测试、AddressSanitizer 和 UE NoLink 编译，全部通过。项目代码未新增原始指针存储、隐式 lambda 捕获、断言或阻断式检查。原始命令自身的分支、标记和哨兵行为保留。

按用户最后限定的范围，代码与独立验证已完成；资产接入、完整链接和 UE 实际运行验证尚未完成。
